# Style Guide Boilerplate v4 — Plan

## Goal
Modernize Style Guide Boilerplate by replacing the PHP implementation with a
Vite plugin. It keeps the original purpose: turn a folder of HTML examples and
Markdown docs, styled by a project's real CSS, into a browsable living style
guide. Development gets edit → save → see it. The build is a fully static site.

**Not a component framework.** It works with any project (plain HTML/CSS, Vue,
React, Astro, PHP…). It's meant mainly to show how a site's CSS styles standard
markup. Teams wanting a full component workbench will likely use Storybook.

## Distribution
- **Package:** `@bjankord/style-guide-boilerplate`, published as **4.0.0** from
  this repo.
- **Form:** a **Vite plugin only** (no CLI for now).
- **Example repo:** a separate repo that is both the cloneable starter and the
  live demo (deployed to GitHub Pages with Actions). It contains v3's sample
  markup migrated to the new layout, a sample `style.css`, and colors and fonts
  configured in `vite.config.js`. Monorepo rejected as too complex for the
  target audience.
- **Language:** plain ESM JavaScript with JSDoc types and a generated `.d.ts`.
  The plugin itself has no build step.
- **Support:** Node ≥ 22, with `vite` as a peerDependency on the **latest major
  only**.

## Usage
```js
// vite.config.js
import { defineConfig } from 'vite'
import styleGuide from '@bjankord/style-guide-boilerplate'

export default defineConfig({
  plugins: [
    styleGuide({
      content: './style-guide',          // default
      styles: ['./src/styles/main.scss'], // local paths go through Vite; URLs become <link>
      scripts: ['./src/js/main.js'],      // optional, loaded once on the page
      colors: [{ name: 'Brand', value: 'var(--brand-primary)' }],
      fonts: [{ name: 'Body', value: '"Inter", sans-serif' }],
      title: 'My Style Guide',
      logo: './logo.svg',
      path: '/',                          // e.g. '/style-guide/' when mounted in an app
      build: true,                        // false = dev only, left out of production builds
    }),
  ],
})
```

- Options are passed inline. There's no separate config file.
- Works as a **dedicated Vite project** (`path: '/'`) or **mounted in an
  existing app** (`path: '/style-guide/'`).
- `path` resolves under Vite's `base`. The generated HTML uses **relative asset
  URLs**, so `dist/` works from any sub-folder.
- The HTML entry is **virtual** (generated by the plugin), so there's no
  `index.html` for users to keep in sync.

## Content layout
```text
style-guide/
├── about.md
├── 01-base/
│   ├── 01-headings.html
│   ├── 01-headings.md
│   ├── 02-lists.html
│   └── 02-lists.md
└── 02-components/
    ├── buttons.html
    └── buttons.md
```
- Docs are **sibling `.md` files** next to their example. HTML docs are dropped,
  since Markdown already allows raw HTML.
- Folder names are free-form, and each folder becomes a section.
- **Ordering:** an optional number prefix (`01-`) sets the order and is stripped
  from titles. Otherwise items sort alphabetically.
- **Front matter** in the `.md` file (`title`, `order`) overrides the defaults.
- Titles come from filenames (`form-buttons` → "Form buttons").

## Page
- **A single page**, in fixed order: **About → Colors → Fonts → content
  folders**. Each built-in section is skipped when its data is missing.
  - About comes from `about.md`.
  - Colors and fonts come from config data. Values may be CSS variables, so
    swatches render through the project's real CSS.
- Navigation is generated from the folders.
- Each example shows:
  1. Documentation (Markdown)
  2. The rendered HTML
  3. **View source** in a `<details>` element, with Shiki highlighting done at
     build time, plus a **Copy** button (`navigator.clipboard`)
- Client-side JS stays minimal: Copy, plus the mobile nav toggle.

## CSS
- **Project CSS:** local paths go through Vite by default (the project's Sass or
  PostCSS setup, with hot reload). Absolute URLs are linked as-is, for PHP, Rails
  and similar setups where the asset pipeline lives elsewhere.
- **The guide's own CSS:** output as a **separate file**. All of it uses the
  **`sg-` prefix** and **no `@layer`**. Occasional leaks from project CSS are
  accepted.
- **Rewrite** v3's `sg-style.css` lightly while keeping the v3 look (sidebar plus
  main area): grid, custom properties, `prefers-color-scheme` dark mode for the
  guide's UI, and no old-IE CSS.
- **Theming:** `title`, `logo`, and `--sg-*` custom properties (`--sg-accent`,
  `--sg-font`, …).

## Markdown and highlighting
- **markdown-it** for Markdown and **gray-matter** for front matter.
- **Shiki** highlights both the source panels and fenced code blocks in docs,
  with one light and one dark theme.

## Development and build
- `vite` (dev): the guide is generated in memory and the content folder is
  watched.
  - Project CSS edits → hot reload in place.
  - `.html`, `.md` or `about.md` edits → regenerate → full page reload.
- `vite build`: fully static output in `dist/` (or `dist/<path>/` when mounted),
  hostable anywhere. Mounted guides ship with the app by default, and
  `build: false` leaves them out.

## Testing
- **Vitest** with a fixture content folder (`test/fixture/`, which has its own
  `vite.config.js`):
  - Scanner: ordering, prefix stripping, front matter, `.md` pairing
  - A snapshot of the generated HTML
  - An integration test: `vite build` on the fixture, then check `dist/` (project
    CSS present, `sg-` CSS separate, source escaped correctly)
- **Playwright e2e** on the same fixture (about four tests): the page renders,
  Copy works, CSS hot reload works, and content edits trigger a reload.
- The example repo's CI runs `npm run build` against the latest package version
  as a smoke test.

## Out of scope for 4.0 (later)
- A CLI wrapper (`npx style-guide dev|build`)
- Search and filtering
- A responsive viewport preview
- Colors and fonts extracted automatically from CSS custom properties
- A `template` option to replace the page template
- Multi-page output
- Per-example scripts

## Suggested build order
1. Content scanner (tree, ordering, front matter, `.md` pairing) + unit tests
2. Markdown + Shiki rendering
3. Page template and the `sg-` CSS rewrite
4. Vite plugin: virtual entry, dev server, watching and reload
5. Build output, `path`/`base` handling, the `build` option, URL styles
6. Fixture snapshot, integration and Playwright tests
7. README, migration note and CHANGELOG
8. Example repo + Pages deploy, then the `gh-pages` redirect
